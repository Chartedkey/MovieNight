# Реализация «Собрать ночь» для 0.3.0

Статус: подготовлено в исходниках, **не собрано и не опубликовано**. Текущая опубликованная версия остаётся 0.2.6. Основа интерфейса — [согласованный макет](prototypes/README.md), требования — [концепт](NIGHT-PLANNER.md).

## Что реализовано

- Настоящая библиотека: очередь, запас и `disk`; кандидаты фильмографии доступны только после явной загрузки для конкретного режиссёра. Просмотренное — только через разрешённый пересмотр и метку `rewatch`.
- Источники: ближайшие, вся библиотека, сначала ближайшие, точная смесь. Для места можно отдельно выбрать ближайшие, остальную библиотеку или пересмотр.
- Фиксированное число мест от 1 до 20; произвольный лимит минут (0 — без лимита), перерывы, часы рядом с минутами. Автоматическое неограниченное количество фильмов не реализовано: число мест всегда задано.
- Жанры TMDB и ручные метки нуар/неонуар. Кинематограф: азиатский, европейский, американский; отдельно необязательное уточнение страны. Страны читаются и из новых ISO-кодов, и из старых русских/английских названий. Совместное производство может входить в несколько регионов.
- Эмоциональная нагрузка и внимание задаются пользователем, не определяются автоматически. Есть отдельный список для разметки, ручная длительность, нуар/неонуар, ручная отметка любимого режиссёра.
- Закрепление, ручной выбор, замена одного фильма с сохранением остальных, перемещение места вверх, причины выбора.
- Сохранение черновика и шаблонов. Шаблоны содержат условия без фильмов и закреплений; их можно удалить.
- Утверждение сохраняет отдельную ночь с датой начала, снимками названий, длительностей, причин и порядка. Оно не меняет статусы фильмов или очередь.
- Чек-лист подготовки: наличие в «Сегодня», необходимость перенести/скачать/проверить источник, субтитры, копии и открытие папок. Ничего не копируется автоматически. Недоступный источник не считается готовым файлом.
- История утверждённых ночей. Ночь без результатов можно изменить, сохранив тот же ID и предыдущую ревизию. После начала разбора правка состава запрещена; можно создать новую ночь без уничтожения прежней истории.
- Утренний разбор: плановые фильмы первыми, затем остальное из «Сегодня» и прежние задачи. «Посмотрел», «Бросил», «Не посмотрел», необязательные оценки, отмена результата.

## Алгоритм

`src/planner.js` — общий модуль Node/renderer, не читает и не меняет файлы. Он фильтрует кандидатов по явным условиям, затем ищет весь набор с возвратом и отсечениями по времени, повтору фильма/режиссёров, группам альтернатив «или» и квотам. Проверяются все режиссёры `directorIds`, а не только основной `dir`.

Предпочтения среди допустимых наборов: доступный файл (100), активная очередь (18), ближайшие в соответствующем режиме (32), «Хочу» (12). Небольшая воспроизводимая добавка seed разнообразит равноценные решения. Наличие имеет больший вес, чем перечисленные остальные преимущества вместе. Личные оценки не назначают любимого режиссёра и не определяют настроение.

Поиск ограничен числом узлов и временем (обычно 700 мс, верхний предел 1500 мс для поиска). При исчерпании бюджета отсутствие результата не выдаётся за доказанную невозможность. Пулы и отображение интерфейса также требуют времени; бюджет относится к поиску комбинаций. Условия не ослабляются молча.

При ограниченной длительности фильмы с неизвестной длительностью исключаются. Используется ручная длительность, затем максимальная известная длительность доступных копий (консервативно для разных изданий), затем TMDB. При нулевом лимите неизвестная длительность допускается с предупреждением в сумме и снимке ночи.

Перед утверждением `check()` повторно проверяет условия по актуальным данным сервиса. Наличие означает сведения последнего сканирования с учётом недоступных/сомнительных источников, а не мгновенный запрос к NAS на каждый подбор. При неподключённых дисках сообщение не утверждает, что фильм нигде не скачан.

## Данные и совместимость

Поля добавляются через значения по умолчанию `emptyState()`, без пересоздания библиотеки и без изменения старых оценок/связей:

- `nightDraft`: настройки, места, ID фильмов, закрепления, при необходимости `editingNightId`.
- `nightTemplates`: ID, название, настройки без выбора фильмов.
- `nights`: ID, локальная дата начала от клиента, время создания, настройки, снимки мест, отметки подготовки, результаты и оценки; ревизии плана до разбора.
- `activeNight`: последний утверждённый план.
- `film.nightTags`: `weight`, `attention`, `styles`, необязательная ручная `runtime`.
- `countryCodes` и `genreIds` сохраняются для новых метаданных; старые текстовые страны/жанры продолжают читаться.

`src/nights.js` подмешивается в Service. Методы разрешены явно через `SERVICE_METHODS` в Electron. `renderer/night-ui.js` подключён до `app.js`, общий алгоритм подключён отдельным локальным скриптом; inline-JS не добавлен в CSP.

Просмотр создаёт ровно одну отметку `watched` с `nightId` и индексом места. Повторное нажатие идемпотентно. При отмене удаляется только соответствующая отметка, восстанавливаются прежние статус/оценка и ближайшие, если это не конфликтует с последующим просмотром альтернативы. Изменение старого результата запрещается, если фильм уже просмотрен в более поздней сохранённой ночи. Для пропуска нового пересмотра сохраняется задача переноса от прежнего просмотра.

`skipped` хранится у места ночи, а не в глобальном статусе фильма. Первичный пропуск не меняет фильм, очередь, ближайшие, оценку и задачи. Отмена оценки/просмотра не удаляет прежнюю независимую историю.

## Предпочтения имён конкретных файлов

Дополнительно реализованы ранее согласованные действия в «Названиях»:

- «Оставить как есть»: `entry.renamePreference = keep`, строка уходит из предложений; отдельный блок позволяет снова включить автоматическое предложение.
- «Ввести имя вручную»: `custom` и `customName`, расширение сохраняется отдельно, дополнительный год не добавляется. Недопустимые пути, символы и зарезервированные имена Windows отклоняются. Есть план и обязательное подтверждение.
- Выбор сохраняется после перезапуска и изменения размера/mtime записи при обходе. Это настройка конкретного пути; самостоятельное перемещение/переименование вне приложения не гарантирует перенос предпочтения.
- Название фильма в библиотеке и имена остальных копий не меняются. Применение имени обновляет разобранные название/год из фактического нового имени, а не подставляет год TMDB поверх ручного ввода.

## Проверки и границы готовности

К штатной команде `npm test` добавлен `test/planner.test.js`. Итог: **67 тестов прошли**. Проверены чистый алгоритм, квоты, страны, неизвестные сведения, закрепление, замены, совместная режиссура, «или», ручные любимые, ограничение поиска, сохранение/перезапуск, пропуск, оценка/отмена, ревизия плана, предпочтения имени.

Отдельно выполнен сценарий в Chromium с реальным Service и изолированной базой: подбор → закрепление → смесь → страна/нуар → утверждение → изменение утверждённого плана → подготовка → результаты/оценка/отмена → перезапуск → ручное имя/сохранение имени. Также выполнен запуск production-скриптов с IPC в настоящем Electron на виртуальном Linux-дисплее. Это проверки исходников, не упаковка приложения.

Windows-установщик и работа с настоящей библиотекой/NAS пользователя ещё не проверялись для этой доработки. Перед выпуском 0.3.0 отдельно согласовать сборку, проверить Windows CI и манифест автообновления. Номер версии в `package.json` пока не повышен; изменена только команда тестов.
